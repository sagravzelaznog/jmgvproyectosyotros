Masterclass 05: Traducción de escenarios cotidianos a proposiciones condicionales (Si... entonces)

1. Causa y Efecto: El Operador Condicional

Gran parte de nuestro razonamiento diario se basa en reglas de causa y efecto. "Si llueve, entonces me mojo". A este tipo de estructura le llamamos Proposición Condicional.

Se compone de dos partes: un antecedente (causa) y un consecuente (efecto). Matemáticamente, usamos el símbolo de flecha \(\rightarrow\) para representarlo: \(p \rightarrow q\).

2. Modelando Promesas y Consecuencias

Visualiza el proyecto de ecología en tu comunidad. El municipio te hace una promesa:

  • \(p\) (Antecedente): Limpian el terreno baldío.
  • \(q\) (Consecuente): Les donan 50 árboles para plantar.

La promesa completa es: "Si limpian el terreno, entonces les donamos 50 árboles" (\(p \rightarrow q\)).

La regla lógica de la condicional es curiosa: Una promesa solo se rompe (es Falsa) si tú cumples tu parte (el antecedente es Verdadero) y la otra persona NO cumple la suya (el consecuente es Falso). En cualquier otro caso, la promesa sigue siendo lógicamente válida.

3. Explorador Interactivo: Simulando la Condicional

Paso a Paso en el Simulador:

  1. Define el antecedente: En la barra de entrada escribe p = true (Limpiaron el terreno).
  2. Define el consecuente: Escribe q = false (No les dieron los árboles).
  3. Evalúa la condicional: GeoGebra Classic requiere usar el operador de implicación. Escribe p -> q y presiona Enter.
  4. Analiza la decepción: El resultado es false. La promesa se rompió. Cambia p = false (No limpiaste el terreno) y mantén q = false. ¡El resultado del condicional vuelve a ser true porque nadie rompió ninguna promesa inicial!
